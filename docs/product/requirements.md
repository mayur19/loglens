# Requirements

Functional (FR) and non-functional (NFR) requirements for LogLens. Priorities use MoSCoW (Must, Should, Could, Won't). Status is **Implemented** (code + tests on `main`) or **Pending** (ticket in [backlog](../planning/backlog.md); pending endpoints answer `501 NOT_IMPLEMENTED` with the ticket id). Traceability to modules and tests: [requirements-traceability.md](requirements-traceability.md).

**Summary:** 72 functional requirements (30 implemented, 42 pending) · 20 non-functional requirements.

### LensQL & search

| ID     | Requirement                                 | Priority | Status      | Tickets                | Acceptance criteria                                                                                                                                                                                                                                                                                                                                                           |
| ------ | ------------------------------------------- | -------- | ----------- | ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-015 | Free-text search over messages              | Must     | Implemented | LG-020, LG-021, LG-023 | Bare words and quoted phrases match message case-insensitively as substrings; * acts as a wildcard; %, _ and backslash in the text are matched literally.                                                                                                                                                                                                                     |
| FR-016 | Field comparisons                           | Must     | Implemented | LG-023                 | field=value, !=, >, >=, <, <= work on built-in columns and dotted attribute paths; numeric comparisons on attributes match JSON numbers and numeric-looking strings and skip non-numeric values without failing the query; ordering operators on text columns return 422 SEMANTIC_ERROR; level values are case-insensitive; wildcard values (e.g. host=web-*) match anchored. |
| FR-017 | Boolean logic                               | Must     | Implemented | LG-021                 | AND (explicit or implicit), OR and NOT with parentheses are supported; AND binds tighter than OR; NOT field=x also matches events where field is missing (two-valued semantics); nesting deeper than 32 levels returns 422.                                                                                                                                                   |
| FR-018 | Regular-expression matching                 | Should   | Implemented | LG-023                 | field=~"pattern" and field!~"pattern" use PostgreSQL regular expressions; patterns longer than 256 characters return 422 LIMIT_EXCEEDED; patterns PostgreSQL rejects return 422 QUERY_FAILED.                                                                                                                                                                                 |
| FR-019 | IN lists                                    | Should   | Implemented | LG-021, LG-023         | field in (a, b, c) matches any listed value; all-numeric lists compare numerically on attributes; lists over 100 values or containing wildcards return 422.                                                                                                                                                                                                                   |
| FR-020 | Field existence                             | Should   | Implemented | LG-021                 | field=* matches events where the column is non-null or the attribute exists and is not JSON null; field!=* matches the complement.                                                                                                                                                                                                                                            |
| FR-021 | Time bounds in the query                    | Must     | Implemented | LG-022                 | earliest= and latest= accept now, -Ns/m/h/d/w and ISO-8601 and override the request range; they are only allowed at the top level of the search; ranges where start >= end or longer than 90 days return 422; without bounds the request from/to (default last hour) applies.                                                                                                 |
| FR-022 | Aggregations with stats                     | Must     | Implemented | LG-023                 | \| stats supports count(), count(f), dc(f), sum, avg, min, max, p50, p90, p95, p99 with optional AS aliases and by up to 5 fields; duplicate output names return 422; numeric aggregates on text columns return 422.                                                                                                                                                          |
| FR-023 | Time bucketing with span                    | Must     | Implemented | LG-023                 | span=30s\|1m\|1h\|1d adds a _time column aligned to the Unix epoch; output is ordered by _time; a span that would produce more than 10,000 buckets per group returns 422 LIMIT_EXCEEDED.                                                                                                                                                                                      |
| FR-024 | Pipeline commands where, sort, head, fields | Must     | Implemented | LG-022, LG-023         | where filters before or after stats (post-stats only on output columns); sort accepts -field and asc/desc; head N caps rows (default 10, max 10,000, never above QUERY_MAX_ROWS); fields projects columns; invalid stage ordering (e.g. where after head, stats after head) returns 422 with the command's span.                                                              |
| FR-025 | Event-count histogram                       | Must     | Implemented | LG-024, LG-029         | POST /api/v1/search/histogram returns a dense series without gaps covering the range, with a bucket width chosen from 1 s … 7 d so that buckets <= the requested target (default 60, max 500); the counts sum to the number of matching events; stats commands are ignored.                                                                                                   |
| FR-026 | Query validation with error spans           | Must     | Implemented | LG-021, LG-029         | POST /api/v1/search/validate returns valid:true with mode and command list, or valid:false with code (LEX_ERROR, PARSE_ERROR, SEMANTIC_ERROR, LIMIT_EXCEEDED, TIME_RANGE_ERROR), message and {start,end} character span, without touching the database; search returns the same span in error.details on 422.                                                                 |

## Won't (this product generation)

- Distributed trace storage and metrics time-series ingestion.
- External identity providers (OAuth/SAML) and hosted email/SMS delivery.
- Cross-installation federation of searches.
