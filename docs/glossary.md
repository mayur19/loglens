# Glossary

| Term                        | Meaning in LogLens                                                                                                                                                                                                   |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Aggregation**             | A function inside `stats` that reduces many events to one value per group: `count()`, `count(f)`, `dc(f)` (distinct count), `sum`, `avg`, `min`, `max`, `p50`/`p90`/`p95`/`p99` (percentiles via `percentile_cont`). |
| **Alert rule**              | (Planned, LG-160) A LensQL query plus schedule, lookback window and condition that is evaluated periodically to produce alert state per group.                                                                       |
| **Alert state machine**     | (Planned, LG-163) Per rule × group lifecycle `ok → pending → firing → resolved`, keyed by a dedup key so repeated breaches do not re-notify.                                                                         |
| **Analyser**                | `packages/shared/src/lensql/analyzer.ts`: validates command order and splits a pipeline into the pre-aggregation stage and the post-aggregation stage (`QueryPlan`).                                                 |
| **API key (ingestion key)** | Bearer credential `llk_<prefix>_<secret>` used by log shippers. Only the 8-character prefix and SHA-256 of the full token are stored.                                                                                |
| **Attributes**              | The `jsonb` column of `log_events` holding every event field that is not a built-in column. Queried by dotted path, e.g. `http.status`.                                                                              |
| **AST**                     | Abstract syntax tree produced by the LensQL parser (`ast.ts`): a search `Expr` tree, optional `earliest`/`latest` bounds and a list of pipeline commands. Every node carries a span.                                 |
| **Backpressure**            | (Planned, LG-100) Refusing work with `429 Retry-After` when the ingest queue is full instead of buffering without bound.                                                                                             |
| **Bucket**                  | One time interval of a histogram or `span` series. Buckets are aligned to the Unix epoch with `date_bin` so results are stable across queries.                                                                       |
| **Bucket budget**           | Limit of 10,000 buckets per group for `span` queries; exceeding it is a `LIMIT_EXCEEDED` error.                                                                                                                      |
| **Built-in fields**         | Columns with dedicated storage and indexes: `timestamp` (`_time`), `level`, `service`, `host`, `source`, `message` (`msg`), `trace_id`.                                                                              |
| **Command**                 | A pipeline stage after `\|`: `stats`, `where`, `sort`, `head`, `fields` (implemented); `rex`, `eval`, `timechart`, `top`, `rare` (planned).                                                                          |
| **Compiler**                | `packages/shared/src/lensql/compiler.ts`: turns a validated plan into one parameterised SQL statement plus output column metadata.                                                                                   |
| **CSRF double submit**      | Mutating browser requests must echo the readable `ll_csrf` cookie in the `x-csrf-token` header; a cross-site page cannot read the cookie.                                                                            |
| **Dead-letter store**       | (Planned, LG-105) Table of rejected ingest lines kept for inspection.                                                                                                                                                |
| **Dedup key**               | Stable identifier of an alert instance (rule id + group values) used to suppress duplicate notifications.                                                                                                            |
| **Default partition**       | `log_events_default`, the catch-all partition for rows outside every daily partition. It should stay empty; the partition manager (LG-191) drains it.                                                                |
| **Event**                   | One normalised log record: timestamp, level, service, host, source, message, trace id and attributes.                                                                                                                |
| **EWMA**                    | Exponentially weighted moving average. For anomaly rules (LG-165) the mean `μₜ = α·xₜ + (1−α)·μₜ₋₁` and a matching variance are tracked per group; a value more than `k` standard deviations from `μ` is anomalous.  |
| **Fan-out cap**             | Login-throttle limit on how many distinct emails one normalised IP may try per 15-minute window (20).                                                                                                                |
| **Flapping**                | An alert repeatedly switching between firing and resolved because the signal hovers around the threshold.                                                                                                            |
| **Free text**               | A bare word or quoted phrase in the search part; matches `message` case-insensitively as a substring.                                                                                                                |
| **Grok pattern**            | (Planned, LG-121) Named, reusable regular-expression fragments (`%{IP:client}`) that extract typed fields from unstructured lines.                                                                                   |
| **Histogram**               | Event counts per time bucket for the search portion of a query; served by `POST /api/v1/search/histogram` as a dense series.                                                                                         |
| **Hysteresis**              | Using different thresholds (and minimum durations) for entering and leaving the firing state to prevent flapping (LG-166).                                                                                           |
| **Ingestion window**        | Accepted event time range: up to 30 days old and up to 10 minutes in the future (later timestamps are clamped and flagged `_clock_skew`).                                                                            |
| **Lease**                   | (Planned, LG-161) Time-limited claim on a due alert rule taken with `FOR UPDATE SKIP LOCKED`, so exactly one worker evaluates it.                                                                                    |
| **LensQL**                  | LogLens Query Language: `search [\| command]…`. Hand-written lexer and recursive-descent parser in `packages/shared/src/lensql/`.                                                                                    |
| **Lexer**                   | `lexer.ts`: converts query text into tokens (`WORD`, `NUMBER`, `STRING`, `OP`, `PIPE`, …) with character spans and size limits.                                                                                      |
| **Live tail**               | (Planned, LG-140) Streaming new matching events to the browser over WebSocket, fed by PostgreSQL `LISTEN/NOTIFY`.                                                                                                    |
| **NDJSON**                  | Newline-delimited JSON, one event object per line; the primary ingestion format.                                                                                                                                     |
| **Normalisation**           | Mapping a raw JSON record onto the event shape: key aliases, level aliases, timestamp parsing, size and depth limits (`ingest/normalize.ts`).                                                                        |
| **Outbox**                  | (Planned, LG-171) Table of outgoing messages (webhook, email) written in the same transaction as the triggering change and delivered by a local worker. Replaces external providers.                                 |
| **Partition**               | A daily child table `log_events_pYYYYMMDD` of the range-partitioned `log_events`. Queries prune to the partitions overlapping their time range; retention drops whole partitions.                                    |
| **Partition pruning**       | PostgreSQL skipping partitions that cannot match the `timestamp >= $ AND timestamp < $` predicate the compiler always emits.                                                                                         |
| **Placeholder fragment**    | Immutable `{text, params}` piece of SQL where values are written as `$?`; `finalizeSql` numbers them `$1…$n`. User text never enters `text`.                                                                         |
| **Post-stats stage**        | Commands after `stats` (`where`, `sort`, `head`) that operate on the aggregation's output columns.                                                                                                                   |
| **Retention**               | (Planned, LG-190) How long a tenant's events are kept before deletion.                                                                                                                                               |
| **Span (time)**             | `span=5m` in `stats`: groups results into fixed time buckets, producing a `_time` column.                                                                                                                            |
| **Span (source)**           | `{start, end}` character offsets of a token or AST node in the query text, returned with errors so the UI can underline the problem.                                                                                 |
| **Stage**                   | A section of the pipeline that is compiled as one SQL level: the event stage (filters, fields, sort, head) and the aggregation stage (stats + post-stats commands).                                                  |
| **Tenant**                  | An organization. Every row and every compiled statement is scoped by `organization_id`.                                                                                                                              |
| **TRUST_PROXY**             | Configuration of which reverse-proxy hops are trusted for client IPs: `false`, a hop count, or IP/CIDR list. Required explicitly in production.                                                                      |
| **Two-valued NOT**          | Leaf predicates are wrapped in `COALESCE(pred, false)` so `NOT field=x` matches events where `field` is missing, unlike raw SQL three-valued logic.                                                                  |
| **Wildcard**                | `*` inside a bare value or free-text term; compiled to `%` in an escaped `ILIKE` pattern.                                                                                                                            |
